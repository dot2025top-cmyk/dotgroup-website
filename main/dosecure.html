FEATURES 1-11 - LOGIN AUTH

1. Password - Argon2id No Plaintext

Modern hashing, no plaintext, policy, change, protect reset, rate-limit, detect credential stuffing, don't reveal if username exists, notify. Do NOT replace working auth without migration.

2. 2FA TOTP - Not SMS only for high-risk

Secure enrollment, verification before activation, safe removal, recovery codes, alerts. SMS may be offered but NOT only for financial due to SIM-swap.

3. Passkeys WebAuthn Backend Validated

Register, view, remove after reauth, recover via alternative. Must be validated by backend - NOT visual button only.

4. Device Manager - No Full IDs Exposed

Nickname, type, browser/app, approx location, last active, reg date, current indicator. Rename, remove trusted, revoke, mark unfamiliar.

5. Login History - Report Unfamiliar

Date/time, outcome, method, device/browser, approx location, risk warnings. Retain per privacy policy.

6. Anti-Phishing DOT-9X2L - Not password

Display in official security emails. Not public profile, not password/recovery secret.

7. Unusual Login Alerts - Risk Based

Unfamiliar device, frequency, failed auth, location change, new device + high-risk tx. Extra auth/notify/restrict/review.

8. Session Management - Secure Cookies

View active, sign out individual/all other, creation times. HttpOnly Secure SameSite.

9. Facial Auth - Platform Result NOT Raw Images

Via passkeys/platform authenticators. App receives result, NOT raw facial images. Don't promise universal Face ID. Alternative if unavailable.

10. Fingerprint Auth - Platform - No Raw Storage in DB

Device fingerprint to unlock/approve. Don't store raw images in DOTGROUP DB. OS handles comparison.

11. Step-Up Auth

Stronger auth for: change email, recovery methods, new trusted device, disable 2FA, change TX PIN, add withdrawal destination, high-risk tx.

33-38 Biometrics & Device

33. Secure Biometric Enrollment - No Raw Storage

Require explicit action, explain benefits/limitations, verify enrollment, allow disable, provide alternative, notify changes.

34. Biometric Tx Approval - Server Verified + Tx Binding

Server verifies assertion valid & associated with session/challenge. Backend validates tx details. Where strong binding required, use mechanism binding approval to intended tx.

35. High-Risk Tx Protection - Configurable

Ordinary: standard auth + confirmation. Elevated: additional auth or verified device. High-risk: stronger auth + destination checks + cooling-off. Combining face+fingerprint+PIN ≠ automatically impossible.

36. Trusted Device Binding - No Permanent HW ID Claim

Register via secure auth. Detect changes via signals. Notify new devices, revoke trusted, extra checks unfamiliar, avoid relying exclusively on HW ID/SIM. Browser cannot obtain universally reliable permanent HW ID.

37. SIM-Swap Protection - Independent Channel

Where signals available, detect phone number changes/indicators SIM takeover. Notify independent channel, require stronger auth, restrict high-risk temporarily. Don't assume detect every SIM swap without service. Don't auto-lock 72h for every change.

38. Recovery Card - Future Secure Design

May contain secure recovery identifier/cryptographic component. Don't print passwords/PINs/secrets readable. Don't make QR with permanent bearer secret sole factor. Must not bypass identity/recovery/tx auth. Don't claim works without internet unless architecture supports.
